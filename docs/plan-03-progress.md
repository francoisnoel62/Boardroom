## Increment 2 — structured human requests

Provider responses now carry a bounded request list with reason, scope, references, expected document and declared adviser/phase consumers. Accepted requests are persisted with the successful call receipt. Existing phase bodies and v1 records remain readable; the wrapper changes all six wire schemas and their synthetic preflight together. No request field can execute a tool or authorize a source.

Observed red → green using `tests/human-requests.test.ts`: no persisted requests; debate continued instead of waiting for a declared consumer; preflight omitted the request schema; final views/analyses reported failed work rather than a resumable human wait; ordinary prose incorrectly cleared an earlier structural answer; a contribution waiting for a blocked final view became unconsumed; an answer during credential preparation stranded a consumer as failed. Each failure preceded the corresponding change. All use public service results, real graphs/SQLite and captured external HTTP inputs. Additional checks cover proposal/revision continuation, stale/foreign replies, bounded invalid provider requests, refusal/deferral under a far-future clock, source consent, request-body exclusion from events and redacted memo/JSON.

Observed red → green using `tests/human-requests-cli.test.ts`: absent request command/option and an answer refused during streams. The final CLI case issues each defer/deny/answer concurrently from two independent processes and observes one response. A real PTY answers while independent analyses are streaming.

Only normal human-wait continuation is implemented: explicit phase commands resume blocked consumers under existing consent and limits, preserving completed/failed/uncertain outcomes. The general persistent scheduler, structural context updates, crash recovery and a binding of newly supplied documents into frozen context remain later work. Consumer pairs apply to future admissions in the same context/framing; they do not invalidate calls already dispatched. No paid provider request has been made.
